Flavoneer · QC production floor

AI-assisted 3D floor plan

A desktop-browser application that turns QC state into a freely browsable, schematic representation of two production halls. Approximate machine models are generated from manufacturer references and known dimensions, while exact QC evidence remains in accessible report panels.

Date: 2026-08-19 Mode: Builder Stage: Prototype definition Status: Approved with open risks

Goal

Build a fast, recognizable 3D operational overview without waiting for factory CAD, exact hall measurements, or manually authored production-quality models. A QC manager should identify the hall and line requiring attention, select it, and open the existing detailed production record.

Chosen direction: Approach A with AI-assisted schematic modeling. The AI agent writes editable procedural geometry from reference images and measurements. It does not accept an opaque image-to-3D mesh as the source of truth.

Premises

  1. Version one represents this factory only. A customer-facing floor editor is outside the prototype scope.
  2. Recognizable silhouettes, machine-level scale, line identity, and product flow matter more than hidden mechanical accuracy.
  3. The hall arrangement is labeled as schematic. The application must not imply engineering or safety-plan accuracy.
  4. AI-generated assets must be deterministic and editable. A script, manifest, preview, and runtime model are reviewed together.
  5. The 3D view answers “where is the QC problem?” Exact readings, audit history, filters, and actions remain normal DOM interfaces.
  6. Existing Convex records remain the source of QC truth. Scene configuration only maps visual nodes to halls and production lines.

Selected approach

AI-assisted schematic 3D factory

For each machine, an AI agent receives manufacturer images, published dimensions, installed-machine photographs when available, and a list of visually important parts. It generates a deterministic Blender Python script or parametric Three.js component from simple boxes, cylinders, tanks, rails, belts, and panels.

The geometry is reviewed in a neutral viewer and corrected at source level. Reusable standalone assets are exported as optimized GLB files. Unseen surfaces remain deliberately simple instead of being presented as inferred mechanical detail.

Why this path

  • Faster than artist-authored production assets.
  • More recognizable than generic labeled boxes.
  • Source scripts remain diffable and reproducible.
  • Repeated machines improve several lines at once.

Primary constraint

Generated geometry may look plausible while being spatially wrong. Every asset therefore needs explicit dimensions, confidence notes, a model budget, source attribution, and human approval.

AI asset workflow

  1. Collect references. At least three useful views, source URLs, installed photographs when available, and known dimensions.
  2. Write a manifest. Record manufacturer, model, dimensions, confidence, line assignments, visually important features, and usage notes.
  3. Generate procedural source. The agent creates a Blender Python script or parametric Three.js component rather than an uneditable mesh.
  4. Render neutral previews. Produce consistent front, side, and three-quarter images for comparison with the references.
  5. Review and correct. Check silhouette, external scale, product direction, origin, material count, and selectable nodes.
  6. Export and validate. Generate the GLB, measure bounds, record polygon and texture budgets, and verify the asset in the browser viewer.

Common asset rules

  • Units are meters; origin is the footprint center at floor level.
  • A documented forward axis defines product flow.
  • Root nodes use stable keys such as machine.rxgj-6.
  • Manufacturer images guide shape but are not copied as runtime textures.
  • Selectable subnodes are limited to meaningful QC inspection points.
  • Every asset has a source script, manifest, preview, and rebuild command.

Implementation shape

Application boundary

Create a separate deployable workspace at apps/qc-floor. Reuse @flavoneer/backend, @flavoneer/config, and @flavoneer/ui instead of duplicating authentication, permissions, reporting logic, or design tokens.

Runtime stack

  • Tailwind CSS 4, React Router, and i18next.

Floor and QC mapping

factory-layout.ts stores schematic hall boundaries, camera bounds, editable machine coordinates, product-flow direction, and asset keys. A separate mapping connects each line to the existing productionHallCode and departmentName values.

The floor-status query returns a bounded result for the selected date window from existing quality inspection summaries. The scene consumes compact per-line state: inspection count, pending count, returned count, out-of-limit count, latest inspection time, and severity. No Convex layout table is needed for the first vertical slice.

Interaction and distribution

  • Start in a bounded elevated isometric view.
  • Provide reset, hall-focus, and “show all exceptions” controls.
  • Selecting a line frames it and opens an accessible DOM side panel.
  • Status uses labels and symbols in addition to color.
  • Selecting an exception opens the existing production-record route.
  • Filters stay URL-backed and outside the WebGL canvas.
  • Provide a keyboard-accessible list fallback and WebGL failure state.
  • Use demand-based rendering so an idle scene does not render continuously.
  • Desktop interaction is required; tablet and mobile QA are deferred.

Deploy the app as a separate Vite bundle through the existing Nginx and Coolify pattern. It connects to the same Convex deployment, organization, and identity as the formulation lab.

Evaluate the prototype by asking a QC manager to find a pending record and an out-of-limit line using the current report, then repeat with the 3D overview. Compare completion time, wrong selections, and whether the manager returns to the list view.

Rejected alternatives

Generic primitive diagram

Fast, but machinery would not be recognizable. The selected approach keeps primitive geometry while giving each model a reference-led silhouette.

Artist-authored low-poly twin

Better visual fidelity, but delays interaction testing. Procedural models can become blockouts for artist replacements later.

Scan as the runtime scene

Captures placement but creates heavy, noisy geometry around reflective stainless steel. A scan may be used privately as a placement reference.

Opaque image-to-3D generation

Invents unseen geometry and produces inconsistent topology and scale. It is not accepted as the editable source of truth.

Required inputs

  • Three or more useful reference views.
  • Published dimensions: 4.5 × 2.6 × 1.82 meters.
  • Five silhouette features that must remain recognizable.
  • Confidence notes for details that are not visible.

Required outputs

  • Reference manifest with source attribution.
  • Deterministic Blender or parametric Three.js source.
  • Optimized GLB with root node machine.rxgj-6.
  • Neutral preview renders and an asset-budget report.
  • Documented rebuild command.

Acceptance

  • The external bounds match the published dimensions.
  • The double annular tank and control area read clearly at floor-view scale.
  • Rollo A and Rollo B instantiate the same asset independently.
  • Selection uses stable node names, not mesh order.
  • A bounding-box fallback can replace the asset without breaking the scene.

Risks and open questions

  • Invented geometry: keep unseen surfaces simple, record confidence, and require human preview approval.
  • Installed revision differs from catalog: prefer on-site photos and mark catalog-only details as provisional.
  • Reference licensing: retain source attribution and never ship manufacturer photographs as model textures.
  • Schematic layout mistaken for a measured plan: label it, omit measurement tools, and keep placement in replaceable configuration.
  • Mutable line names: keep mapping explicit and add stable production-line IDs before supporting editable layouts.
  • Asset growth: enforce bounds, triangle, material, texture, and compressed-file budgets after the RXGJ-6 baseline is known.

Open questions

  • Should the schematic product-flow arrows be reversed for any line?
  • Which wrappers are installed on Rollo A, Rollo B, GMF, and SLC?
