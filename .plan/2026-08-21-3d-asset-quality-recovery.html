Target state

One asset contract. Every model.

A model is complete only when its source, installed configuration, reference ranking, relational constraints, previews, exports, and deterministic rebuild all agree.

0 mm allowed offset for declared mating points

Failure evidence

Fix the mechanisms that produced the errors.

  • Repeated geometry bug

    RXGJ-6 and RXGJ-12 independently placed radial dispenser banks along tangent lines. Both passed the original verifier and needed user corrections.

  • Wrong topology

    BT-C passed file and budget checks while its tunnel path, optional outfeed loop, DIPCO placement, and wrapper order did not match the installed line.

  • Context pressure

    Model threads ended with 138,000 to 218,000 input tokens. BT-C reached 235,927 of 258,400 tokens before compaction. Full logs and mixed photo sets displaced useful spatial context.

  • Shared workspace loss

    The complete BT-C source bundle existed in checkpoint fd5109d. By checkpoint 0c044ce, only its GLB and STL remained and its README entries were gone.

  • Copied infrastructure

    Twelve Blender generators and twelve verifiers contain about 9,328 lines. They repeat coordinate, export, render, and GLB traversal logic instead of sharing it.

Execution phases

Recover first. Standardize second. Migrate last.

The sequence matters. New asset production stays paused until the repository has a durable baseline and the shared verifier catches the known RXGJ failures.

Duration: 0.5 day setup Owner: repository maintainer

Enforce isolated work and review

Each machine gets a worktree or branch. Shared library and registry changes land separately before machine branches update to them.

Exit gate

Two machine branches can run at the same time without touching the same working directory or committing one another's outputs.

Release gate

A model cannot pass on appearance alone.

  • Specification validates and names one exact target revision.
  • Every geometry-driving source has a rank and component mapping.
  • Included and excluded optional modules match the installed line.
  • Bounds match the specification within the declared tolerance.
  • All declared mating points and lane centers pass relational checks.
  • Conveyor endpoints connect in the specified station order.
  • Front, rear, side, top, three-quarter, and source-angle renders exist.
  • Source, GLB, STL, specification, report, and previews rebuild together.
  • Two clean rebuilds produce matching GLB and STL hashes.
  • A clean Blender import preserves required node names and groups.
  • The commit contains only the intended machine bundle or shared tooling change.
  • A human reviewer signs off on the contact sheet and constraint report.

Risks and decisions

Decisions that should not drift between threads

Risk Level Control
Restoring BT-C overwrites later assets. High Restore into a separate worktree and copy only reviewed BT-C paths.
Shared library migration changes rendered geometry. High Compare old and new bounds, nodes, contact sheets, and hashes per asset.
Reference ranking rejects useful family photos. Medium Allow family sources for named components, never for dimensions or installed topology.
Strict constraints slow rough blockouts. Medium Permit draft status, but prohibit draft assets from the runtime catalog.
Parallel work returns to one dirty directory. High Require a worktree path and branch in every machine task.
References

Six strong exact-model views beat a large mixed photo archive.

Coordinates

Repeated parts derive from one lane or mould array. They do not copy coordinates.

Validation

Bounds and budgets remain necessary, but relational checks decide spatial correctness.

Integration

Machine work lands as an isolated bundle. Shared files change in separate commits.

This plan improves the procedural asset pipeline only. It does not claim engineering, fabrication, installation, guarding, process, or safety accuracy for the resulting models.
