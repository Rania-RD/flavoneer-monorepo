Flavoneer engineering Decision brief · 02 Aug 2026

Auth and workspace architecture

Better Auth should own the boundary, not the product.

Move workspace lifecycle, members, and invitations into Better Auth. Keep Flavoneer’s formulation permissions and domain workspace record in Convex.

Development cutover applied Hybrid authority

Phases 0–4 are implemented and the development backfill completed on 02 Aug 2026. Production remains gated on inventory and retention review; Better Auth nested teams remain disabled.

01 · Decision

Use Better Auth for organization operations.

Keep a narrow seam between identity administration and food R&D rules.

Decision rule

Better Auth answers “who belongs to this workspace and who may administer it?” Convex answers “what may this person do to formulations, runs, approvals, inventory, and system settings?”

Goal Replace custom member, invitation, and workspace-admin lifecycle code without destabilizing domain authorization.
Mode and stage Production infrastructure planning for an existing application. Current usage and customer constraints were not supplied.
Primary premise The existing top-level “team” is a workspace. It maps to Better Auth’s organization, not to its nested team entity.
Implementation status Better Auth now owns organization, member, and invitation writes through app wrappers. Convex keeps bounded projections and domain permissions; legacy table retirement remains deferred until the rollback window closes.
02 · Trade-offs

Better lifecycle coverage, with a real integration bill.

The organization plugin removes common edge cases, but the Convex adapter requires a local component install because this plugin adds schema.

Advantages

One identity and membership system Session users, organization members, organization roles, and invitation recipients use the same Better Auth user IDs.
Complete organization lifecycle Create, update, delete, list, leave, remove members, update roles, set an active organization, and transfer ownership use maintained APIs.
Safer invitation behavior Built-in pending states, expiry, resend, cancellation, recipient checks, and optional verified-email enforcement replace custom token handling.
Typed access-control vocabulary Static resources and actions can be checked server-side. Dynamic roles exist if per-organization custom roles become a proven requirement.
Limits are configurable Organization, membership, invitation, and nested-team limits can enforce plan rules closer to the administration boundary.

Disadvantages

Local component install is required The Convex component does not list the organization plugin as an out-of-the-box schema-compatible plugin. The project must own generated Better Auth schema and its upgrade path.
IDs and concepts do not line up Domain records reference Id<"teams">; Better Auth organization IDs are strings. A binding/projection is safer than replacing every foreign key in one release.
Full access-control migration adds coupling Product actions such as execute_runs and manage_version_control are domain policy. Moving them into the auth component would tie normal product changes to auth schema and plugin releases.
Email still needs an email service Better Auth calls sendInvitationEmail; it does not deliver mail by itself. Delivery, templates, sender verification, and retry policy remain project work.
Hooks require failure analysis Convex Better Auth triggers are transactional per database operation, but an endpoint may perform several operations. A later trigger failure does not undo earlier operations from the same endpoint.
03 · Authority

Give every fact one owner.

The local workspace document remains a domain anchor, not a second member directory.

Fact Source of truth Local shape Rule
Identity and session Better Auth Existing component user and session tables Use validated Convex auth state before protected queries run.
Workspace lifecycle Better Auth organization Keep teams as a projection with authOrganizationId and domain settings. No direct local create/delete after cutover.
Members and owner/admin/member role Better Auth member Optional read projection during migration All writes use Better Auth APIs.
Invitations Better Auth invitation No long-term custom token table Require verified recipient email before acceptance.
Active workspace Better Auth session Temporary local-storage fallback during canary Clear or repair it when membership is removed.
Domain permissions Convex app tables roles, users.roleId, permission helpers Server checks remain mandatory; UI checks are advisory.
Workspace audit history Convex audit log teamAuditLogs with Better Auth operation IDs Append; do not delete history when a workspace is deleted.

Better Auth

Authenticates the user and owns organizations, members, invitations, and coarse organization roles.

user → organization → member / invitation
Compatibility seam

Workspace access helper

Resolves the local workspace ID to the Better Auth organization and returns the caller’s membership and coarse role.

Product

Convex domain policy

Applies product permissions to projects, runs, reports, inventory, approvals, roles, and system configuration.

requirePermission(ctx, "execute_runs")
04 · Alternatives

Three valid paths, one proportionate choice.

The hybrid approach carries migration cost but avoids an all-or-nothing rewrite.

Minimal

Harden the custom Convex system

Keep the current tables and functions. Add email delivery, token expiry, recipient-email checks, ownership transfer, and central access helpers.

  • Relative effort: small.
  • Best when member administration is stable and simple.
  • Rejected because the project keeps owning standard identity lifecycle edge cases.
Recommended

Better Auth lifecycle, Convex domain policy

Use the organization plugin for workspace administration while retaining a local workspace projection and product permission system.

  • Relative effort: medium.
  • Preserves current domain foreign keys and product settings.
  • Reduces custom auth lifecycle code without coupling every permission to Better Auth.
Idealized

Full Better Auth consolidation

Move workspace lifecycle and domain roles into Better Auth dynamic access control; replace local membership and role tables.

  • Relative effort: large.
  • One administration model after completion.
  • Rejected now because dynamic access control adds schema and turns product policy changes into auth-component changes.
05 · Migration

Change the authority before deleting the old path.

Each phase has an observable gate. The custom tables remain recoverable until Better Auth reads and writes are proven in production.

Phase 0 · Baseline

Freeze semantics and install missing guidance

  • Run npx convex ai-files install so the required managed Convex guidance exists.
  • Pin and review compatible better-auth and @convex-dev/better-auth versions before schema generation.
  • Record counts and invariants for workspaces, owners, members, pending invites, and domain records by teamId.
  • Define whether organization creation is open, admin-only, or plan-gated.
Gate: a repeatable inventory report has zero duplicate memberships and exactly one owner per workspace.
Phase 1 · Install

Convert Better Auth to a local Convex component

  • Create convex/betterAuth/, generate its schema, and register the local component.
  • Add the server organization() and client organizationClient() plugins. Leave nested teams disabled.
  • Use lazy HTTP route registration to reduce deployment bundle pressure.
  • Configure organization and membership limits explicitly; do not rely on defaults.
Gate: existing sign-up, sign-in, sign-out, session restoration, and protected Convex queries behave exactly as before.
Phase 2 · Bind

Backfill organizations without changing domain IDs

  • Add nullable authOrganizationId to the local teams table and index it.
  • Create one Better Auth organization for each local team and add existing members with matching owner/admin/member roles.
  • Keep teams._id as the workspace foreign key for projects, runs, inventory, reports, and audits.
  • Cancel and reissue pending custom invitations. Do not copy raw invite tokens.
Gate: every local workspace resolves to one organization, membership sets match, and backfill reruns are idempotent.
Phase 3 · Shadow

Route writes through a compatibility service

  • Replace UI calls to custom mutations with app-owned wrappers around Better Auth server APIs.
  • Mirror organization operations to local projections through component triggers or explicit app mutations.
  • Emit divergence metrics for organization name, owner, members, role, and invitation state.
  • Keep the old write path behind an emergency feature flag for one release window.
Gate: seven consecutive production days with no unexplained membership or role divergence.
Phase 4 · Read cutover

Centralize authorization and active workspace state

  • Add one workspace access helper and replace direct teamMembers queries in projects, runs, audit logs, and team administration.
  • Move active workspace state to Better Auth’s active organization session field; keep local storage as a temporary fallback.
  • Require server-side membership plus domain permission checks for every protected operation.
  • Retain the current Convex roles system during this phase.
Gate: permission matrix, cross-workspace isolation, removal, leave, and active-workspace tests pass with legacy reads disabled.
Phase 5 · Retire

Remove obsolete lifecycle storage

  • Stop creating teamMembers and teamInvites documents.
  • Archive or remove those tables only after a rollback window and verified backup.
  • Keep the local teams projection for domain references and settings.
  • Document the Better Auth schema-generation and package-upgrade procedure in the app README.
Gate: no production code reads legacy lifecycle tables and the previous release can still be restored with its data snapshot.
Later · Optional

Evaluate dynamic organization roles

Only start this phase if users need different product roles per workspace or customers must define their own permission sets. Otherwise, the current Convex domain permission model is simpler.

Gate: observed customer behavior requires per-workspace custom roles, not merely a desire for architectural uniformity.

07 · Verification

Test authority changes, not only happy paths.

A migration is complete when old and new membership states cannot silently disagree.

Required Permission matrix
Test owner, admin, member, removed member, non-member, and unauthenticated users against organization CRUD, invitation CRUD, member-role changes, projects, runs, roles, version control, and audit history.
Required Invitation abuse cases
Cover wrong signed-in email, unverified email, expired, canceled, reused, resent, already-member, role changed before acceptance, and organization deleted before acceptance.
Required Cross-workspace isolation
A member of workspace A must not read or mutate workspace B by passing a local workspace ID, Better Auth organization ID, project ID, run ID, or invitation ID from B.
Migration Backfill idempotency and divergence
Run the backfill twice, interrupt it mid-run, retry it, and compare both stores. No duplicate organization, member, owner, or audit event may be created.
Operational Email delivery and retry behavior
Verify sender domain, bounce handling, rate limits, resend behavior, link origin, Arabic and English templates, and expired-link recovery.
Rollback Restore the previous release safely
Retain legacy data and the compatibility write flag for one release window. Snapshot before table retirement. A rollback runbook must state which system wins if writes occurred after cutover.
Release command gates

Run pnpm --filter @flavoneer/formulation-lab check, pnpm --filter @flavoneer/formulation-lab build, and targeted Playwright organization flows. Add an automated divergence query to the deployment checklist during shadow mode.

08 · Evidence and risks

What this recommendation is based on.

Local code and current primary documentation were reviewed on 02 August 2026. No customer or usage research was provided.

Local auth configuration rd/formulation-lab/convex/auth.ts uses Better Auth with email/password and the Convex component.
Local workspace model convex/schema.ts defines custom teams, members, invitations, audit logs, users, and roles.
Custom invitation gap convex/teamInvites.ts returns a generated token and contains a TODO for sending invitation email.
Repeated membership reads projects.ts, runs.ts, and team modules query teamMembers directly.
Better Auth organization plugin Official organization documentation covers members, invitations, coarse roles, custom access control, dynamic roles, and nested teams.
Convex plugin support boundary Official supported-plugin list directs schema-changing plugins to local install.
Local install requirement Official local-install guide requires generated schema, a local component, adapter exports, and registration changes.
Trigger semantics Official trigger guide documents per-operation transactional behavior and the multi-operation caveat.

Open questions before Phase 1

  1. May every signed-in user create a workspace, or is creation limited by subscription/admin approval?
  2. Do product roles need to differ by workspace? The current users.roleId is global.
  3. Which email service and sender domain will deliver invitations in production?
  4. How many production workspaces, members, and pending invites must the backfill handle?
  5. Must organization deletion retain regulated formulation and audit records? If yes, disable direct Better Auth deletion and implement archival.
Concrete next assignment

Build a read-only inventory query that reports each workspace’s owner, members, pending invites, and referenced domain-record counts. Do not install the organization plugin until that report is reviewed and the deletion-retention rule is decided.

DONE_WITH_CONCERNS · Recommended approach: Better Auth organization lifecycle with Convex domain policy. Main unresolved risks: local component ownership, per-workspace product roles, invitation delivery, and regulated deletion retention.
