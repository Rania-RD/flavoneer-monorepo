Prioritized findings

Fix the boundary first, then the pipeline.

P0 findings can expose or corrupt production data. P1 findings can cause unreliable releases, incidents, or scaling failures. P2 findings reduce operational confidence.

F-01P0 · security

Core domain functions allow anonymous or cross-tenant access.

Convex public functions are Internet-facing. Several modules read and mutate shared tables without calling an auth, membership, ownership, or permission helper.

  • inventory.list/create/update/remove/bulkRemove/bulkUpdateStatus have no auth check.
  • comments.list/add/resolve have no auth check and accept author identity from the client.
  • labReports exposes report reads, creation, sign-off state changes, and deletion without auth.
  • equipment.updateStatus and spreadsheet reads/writes have no access enforcement.
  • ingredients checks only that a user exists, returns all ingredients, and lets any signed-in user update an arbitrary ID.

Impact: unauthenticated data disclosure and mutation, forged audit identity, cross-workspace access, report tampering, and inventory deletion.

Required fix: inventory every public function, derive identity server-side, load the parent resource, and call one shared personal-or-workspace authorization helper before every read or write. Add organizationId to tables that cannot currently express tenancy and migrate them safely.

F-02P0 · security

Share links grant arbitrary editor access without resource authorization.

sharedLinks.createLink accepts an arbitrary string entity ID and role. The source comment explicitly says resource authorization is not implemented. Any authenticated user can mint an editor link for an entity they do not own. The module also uses JWT subject while newer access helpers use the Better Auth user ID, creating inconsistent identity keys.

Impact: privilege escalation and durable cross-user access through a valid-looking share token.

Required fix: validate typed entity IDs, load the referenced project or run, authorize owner/workspace rights, derive the canonical Better Auth user ID, add expiry and revocation metadata, and test viewer/editor boundaries.

Evidence path
packages/backend/convex/sharedLinks.ts:8-97
F-03P0 · abuse

Public sensory submission and file URL resolution lack abuse controls.

Sensory evaluation is intentionally public, but submission accepts a raw formId, does not require the form token, has no rate limit, and accepts unbounded JSON strings and tester names. Any signed-in user can also read evaluations for any form. files.getFileUrl resolves a storage ID without authentication or ownership validation.

Impact: spam and storage growth, guessed-ID access, exposure of signed file URLs, and cross-workspace sensory results.

Required fix: submit by high-entropy token, validate payload size and schema, rate-limit per token and client, enforce form lifecycle limits, authorize result reads, and bind file metadata to an authorized parent record.

Evidence paths
packages/backend/convex/sensory.ts:6-111 packages/backend/convex/files.ts:27-32
F-04P0 · release

There is no enforced release pipeline, and local release gates fail.

No tracked GitHub Actions, GitLab CI, or equivalent pipeline exists. The root check returns 176 errors and 499 warnings. Recursive typechecking fails in the formulation lab because @vitejs/plugin-react resolves a conflicting Vite type. The repository can be built or deployed without tests, typechecking, migration checks, or an approval gate.

Impact: known failures and unreviewed schema or auth changes can ship from a developer machine.

Required fix: add one required CI workflow with frozen install, format/lint, all workspace typechecks, backend codegen/schema validation, unit tests, browser smoke tests, production builds, dependency scanning, and protected deployment jobs.

F-05P1 · testing

The test suite does not cover the backend security boundary.

The formulation lab has 23 spec files and 78 tests, but there are no tracked backend, mobile, or landing test files. The backend does not depend on convex-test or Vitest. The current Playwright run produced 75 passes, two timeouts, and one test that did not run.

Impact: the highest-risk authorization defects have no regression protection, and the only end-to-end gate is red.

Required fix: add table-driven Convex tests for anonymous, non-member, member, admin, owner, shared-viewer, and shared-editor cases. Repair the two UI flows and split pure helper tests from browser tests so fast checks do not require Chromium.

F-06P1 · runtime

Active authentication flows contend on the Better Auth session document.

convex insights --details found eight warnings in the last 72 hours. The largest was 177 OCC conflicts on users:syncCurrentUser attributed to betterAuth/adapter:updateOne on the session table. Settings, projects, organizations, and file upload calls show the same session contention source.

Impact: automatic retries, higher mutation latency, and failure risk during bursts or multi-tab sessions.

Required fix: trace why auth lookup writes the session during these mutations, reduce repeated client sync calls, and avoid broad or write-on-read auth work where the Better Auth API permits. Re-run Insights after the change and set a measurable conflict budget.

F-07P1 · scale

Unbounded and amplified reads will degrade with real tenant data.

Backend source contains 72 .collect() calls. Some are bounded by a parent index and may be acceptable, but several public list paths scan whole tables. inventory.list then performs one material-usage query per item, creating N+1 reads. It also uses Date.now() inside a reactive query, so expiry state can become stale without a database change and query cache reuse is reduced.

Impact: read amplification, larger reactive invalidation sets, stale expiry state, and transaction-limit failures as records grow.

Required fix: add organization-first indexes and pagination, pass time as an argument or materialize expiry status, replace N+1 usage lookups with a bounded summary strategy only where measured, and batch maintenance mutations.

Evidence path
packages/backend/convex/inventory.ts:76-125
F-08P1 · frontend

The formulation-lab main bundle is too large for a production first load.

The successful Vite build emits a 3.75 MB minified main JavaScript bundle, 1.15 MB gzip, and prints the chunk-size warning. Heavy PDF, data-grid, charting, and formulation flows appear to load through the initial route graph.

Impact: slow startup and parse time on mobile or lower-power hardware, with no performance budget to catch regressions.

Required fix: lazy-load route pages and heavy report/grid modules, inspect a bundle visualization, define initial-JS and route-chunk budgets, and enforce them in CI.

F-09P1 · identity

Production auth hardening is not environment-specific.

Email/password auth is enabled with email verification disabled. Invitation verification is also disabled, and any user can create up to ten organizations. Those settings apply to every environment. A hard-coded creator email is persisted as an isCreator flag, even though it currently appears to affect UI state rather than server permissions.

Impact: disposable or mistyped accounts can gain application access, and a dormant identity special-case can become an authorization hazard later.

Required fix: require verified email in production, document signup and organization-creation policy, add recovery and lockout tests, and remove or formally scope the creator-email special case.

Evidence paths
packages/backend/convex/auth.ts:38-57 packages/backend/convex/users.ts:10-37
F-10P1 · operations

Web and backend failures are not captured in a production error workflow.

Mobile initializes Sentry-compatible Bugsink reporting and captures production-line exceptions. The formulation lab and landing site use PostHog for analytics, but application errors are mostly written to console.error; no web error boundary, source-map upload, alert routing, or backend incident runbook is tracked.

Impact: browser and backend regressions can reach users without an actionable alert or symbolicated stack trace.

Required fix: add web error capture and React error boundaries, upload source maps securely, define alerts for error rate, failed auth, OCC conflicts, and critical mutations, and link alerts to an owner and runbook.

F-11P2 · supply chain

Environment and dependency hygiene is incomplete.

rd/formulation-lab/.env is tracked and contains non-empty Convex deployment values. The values inspected are endpoints and a deployment identifier, not confirmed credentials, but the file couples source control to one environment. No Dependabot, Renovate, SBOM, or scheduled audit configuration is tracked. pnpm audit --prod did not return and was cancelled after more than three minutes, so vulnerability status is unknown.

Required fix: remove the tracked .env from the index, keep only examples, validate secret storage, add automated dependency review, and produce a successful audit/SBOM artifact before release.

F-12P2 · delivery

Deployment artifacts lack health, rollback, and browser hardening controls.

Dockerfiles do not define health checks. The formulation-lab Nginx image has useful cache and content-type headers, but no CSP, frame-ancestor policy, Permissions-Policy, or HSTS at this layer, and it does not declare a non-root runtime user. No root runbook documents backup restore tests, rollout order, rollback, incident ownership, or recovery objectives.

Required fix: add platform health probes, confirm non-root container operation, set security headers at the single authoritative edge, document Convex backup/restore and rollback drills, and capture the last successful drill date.

Remediation sequence

A release can be made safe in four controlled phases.

Sequence matters. Tenant data must be representable before access checks can be correct, and security tests must exist before broad refactoring starts.

0 · now

Freeze production deployment

  1. Do not deploy this snapshot to a production dataset.
  2. Restrict any Internet-accessible non-production deployment to test data and known users.
  3. Record an owner for the authorization audit and one reviewer independent of the implementation.
1 · 1-3 days

Close the data boundary

  1. Catalog all 127 public Convex queries, mutations, and actions.
  2. Classify each as public-token, personal, workspace-member, workspace-admin, or internal.
  3. Add organization ownership fields and indexes where missing using widen-migrate-narrow.
  4. Apply shared authorization helpers to every sibling reader and writer, not only the examples in this report.
  5. Lock share links, sensory submission, storage URL access, and client-supplied identity fields.
2 · 3-5 days

Make the release gate deterministic

  1. Add convex-test authorization tests before changing behavior further.
  2. Align Vite and React plugin versions, then require all workspace typechecks.
  3. Resolve Biome failures or scope checked generated artifacts explicitly.
  4. Repair the two failing Playwright flows and split helper tests into a fast non-browser runner.
  5. Create required CI checks and protect the production deploy environment.
3 · week 2

Reduce measured runtime and frontend risk

  1. Trace and reduce Better Auth session writes; verify the OCC rate drops in Convex Insights.
  2. Paginate organization-scoped inventory and replace its N+1 usage reads.
  3. Move time-derived expiry behavior out of an implicit wall-clock reactive query.
  4. Lazy-load heavy formulation routes and enforce a bundle budget.
  5. Run a production-like load test for login, project save, inventory update, and report sign-off.
4 · prelaunch

Prove operability

  1. Add web/backend error reporting, alerts, ownership, and incident runbooks.
  2. Complete dependency audit and SBOM generation.
  3. Run and document backup restore, rollback, and mobile OTA rollback drills.
  4. Deploy to staging from CI, run smoke tests, then use a canary or limited workspace launch.

Production exit criteria

Release only when every item is evidenced.

These are binary gates. A verbal assurance does not count as evidence.

Every public Convex function has a documented access class and automated negative tests.
Anonymous and cross-workspace reads/writes fail in staging.
Share links validate ownership, typed entity IDs, role, expiry, and revocation.
Public sensory submission is token-bound, schema-limited, and rate-limited.
pnpm check, all typechecks, all tests, and all builds pass from a clean checkout.
Required CI checks block merge and production deployment.
Convex Insights has no unresolved high-volume OCC warning for the release candidate.
Initial lab JavaScript meets an agreed, measured budget on a representative mobile connection.
Web, backend, and mobile exceptions reach an owned alert channel with symbolicated stacks.
Dependency audit and SBOM artifacts are stored with the release.
Backup restore and rollback drills have a recorded successful result and recovery time.
Production configuration contains no tracked environment file and fails fast on missing required URLs.
